# RC-dog

8DOF 轮足四足机器人 STM32 固件与比赛功能开发仓库。

## 开发路线

当前主线工作为第一阶段任务赛通讯和第二阶段无 IMU 障碍动作。IMU 姿态增强与高墙均为不阻塞主线验收的可选专项；后续工作不得破坏已通过的障碍动作、已验收的控制方式和安全逻辑。

| 阶段 | 目标 | 主要控制入口 | 完成判据 |
| --- | --- | --- | --- |
| 第一阶段：任务赛通讯 | 完成上位机到 STM32 的 `0x10` USB 控制，使 ROS2 能控制模式、前后、转向和速度 | 上位机 USB 为任务输入，实体 SBUS/CH9 保留最高安全优先级 | 50 Hz 稳定控制；USB 失联 150 ms 内停止；可完成任务赛底盘运动闭环 |
| 当前越障基线 | 已通过直角绕杆、限高杆、大斜坡和木桥 A；保持其动作与参数可回归 | 实体 SBUS 为主 | 每次新增障碍动作后均可重复通过这 4 项 |
| 第二阶段：无 IMU 障碍动作 | 当前聚焦单级上台阶专项；木桥 B 和砂砾碎木坑不在固件实现范围 | 实体 SBUS `HIGH+HIGH`；关节编码器、电机反馈和轮驱保护 | CH3 三档单级上台可安全执行或停止，并完成实体保护验收 |
| 可选专项：IMU 姿态增强 | 视实机风险再接入并验证 `0x11 VIRTUAL_IMU`，先做姿态超限停止，再评估补偿 | USB `0x11`、实体 SBUS/CH9 保持最高优先级 | 不阻塞第二阶段；启用时需完成新鲜度、方向和失效处理验证 |
| 可选专项：高墙 | 视时间和安全条件专项开发 300 mm 高、50 mm 厚高墙的攀爬或动态跨越 | 独立高墙动作与保护状态机 | 不阻塞其他障碍；仅在保护场地中重复验证后尝试 |

第二阶段不要求 `0x11 VIRTUAL_IMU`。当前障碍动作只开放给实体 SBUS：实体 `HIGH+HIGH` 进入障碍模式；USB `0x10` 的 mode 8 仍保持 `RESERVED` 站立 HOLD，不能启动越障。`0x11` 姿态增强和高墙均仅在主线稳定后按需立项。

## 当前代码状态

- 已完成实体 SBUS 接收、CH5/CH8 九宫格模式、CH9 锁存安全、腿部 MIT 控制、四轮控制和轮腿混合步态。
- H+L/H+M 普通移动采用两组对角腿交替的 trot；CH3 连续调节 LOW/MID/HIGH 锚点之间的频率、步幅和抬脚高度，并在半步边界限速锁存。
- 当前硬件不使用机械臂；DM/LZ 驱动和机械臂任务已移除，USB mode 5 保留编号并按站立 HOLD 处理。
- 已实现固定 40 字节 USB 解析、`0x10` 控制、USB/SBUS/NONE 仲裁和 150 ms 看门狗；正式 ASCII 接口仅保留只读 `p/Y`。
- 已实现 Python 上位机 codec、50 Hz 串口控制流、命令行联调和协议单元测试。
- 第一阶段软件已通过主机协议测试和 STM32 Debug/Release 构建，仍需在实体遥控器授权和机器人架空条件下完成硬件联调。
- 当前实机越障基线已通过直角绕杆、限高杆、大斜坡和木桥 A；其余常规障碍为第二阶段主线目标，高墙为可选专项。
- 实体 `HIGH+HIGH` 只进入单级上台阶模式。CH3 在入模时锁存 LOW/MID/HIGH，分别使用 `50/50/0`、`100/100/0`、`150/180/30 mm` 的“落脚高度/抬脚峰值/机身预升”参数；模式内拨动 CH3 不改变当前会话。
- SA/CH10 每次稳定切换 8 个新鲜 SBUS 帧后请求一次完整上台序列，初始档位只同步不触发。CH2 在障碍模式无作用，不存在手动或自动逆序回退；中途退出会在当前足端分段完成后保持，CH9 是唯一立即取消轨迹并锁存安全状态的输入。
- 单级动作沿用 300 mm 水平前送，完成前腿、机身移重、后腿和顶部归一化后恢复普通站姿。进入前要求四轮在线且绝对轮速小于 0.5 rad/s 连续 200 ms；全部足端分段先经过 16 区间全路径 IK 和关节限位检查。
- 木桥 B、砂砾碎木坑、gap 检查点、障碍类型选择及其回退实现已从固件删除，没有隐藏或工程调试入口；相关内容仅在比赛分析文档中作为场地背景保留。
- `0x11` 当前只校验并丢弃；IMU 解码、姿态超限停止和姿态补偿为可选专项。
- 116 mm 驱动轮已用于当前轮速和轮腿同步计算。

默认构建不包含可运动的 USB 工程命令、VOFA 在线调参和原始 CAN 日志。仅在受控维护环境需要这些功能时，使用 `-DDOG_ENABLE_ENGINEERING_USB_DEBUG=ON` 重新配置独立构建目录；正式固件保持默认 `OFF`。

实际实现状态以代码和测试结果为准；规划文档中的接口不得被描述为已经完成。
