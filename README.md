# RC-dog

8DOF 轮足四足机器人 STM32 固件与比赛功能开发仓库。

## 开发路线

当前工作按三个阶段推进；第二阶段拆为不依赖 IMU 的障碍动作和 IMU 姿态增强两步。后续工作不得破坏已通过的障碍动作、已验收的控制方式和安全逻辑。

| 阶段 | 目标 | 主要控制入口 | 完成判据 |
| --- | --- | --- | --- |
| 第一阶段：任务赛通讯 | 完成上位机到 STM32 的 `0x10` USB 控制，使 ROS2 能控制模式、前后、转向和速度 | 上位机 USB 为任务输入，实体 SBUS/CH9 保留最高安全优先级 | 50 Hz 稳定控制；USB 失联 150 ms 内停止；可完成任务赛底盘运动闭环 |
| 当前越障基线 | 已通过直角绕杆、限高杆、大斜坡和木桥 A；保持其动作与参数可回归 | 实体 SBUS 为主 | 每次新增障碍动作后均可重复通过这 4 项 |
| 第二阶段第一步：无 IMU 障碍动作 | 完成砂砾碎木坑、木桥 B 和 T 字形台阶 | 实体 SBUS、关节编码器、电机电流和轮速反馈；继续使用 `0x10` | 可完整通过 150 mm 护栏、木桥 B 横向踏板缝和 100 mm 三级台阶，失败能安全停止或撤回 |
| 第二阶段第二步：IMU 姿态增强 | 接入并验证 `0x11 VIRTUAL_IMU`，先做姿态超限停止，再逐步加入补偿 | USB `0x11`、实体 SBUS/CH9 保持最高优先级 | IMU 新鲜度、方向和失效处理验证完成；不改变第一步已验收动作的基本轨迹 |
| 第三阶段：高墙 | 专项开发 300 mm 高、50 mm 厚高墙的攀爬或动态跨越 | 独立高墙动作与保护状态机 | 在保护场地中重复通过，失败可安全退出，不影响前两阶段功能 |

第一阶段和第二阶段第一步只要求 `0x10 VIRTUAL_RC_SETPOINT`。`0x11 VIRTUAL_IMU` 只属于第二阶段第二步，不阻塞砂砾坑、木桥 B 和 T 字形台阶动作开发。高墙不与普通台阶动作混用，在前两阶段稳定后再单独立项。

## 当前代码状态

- 已完成实体 SBUS 接收、CH5/CH8 九宫格模式、CH9 锁存安全、腿部 MIT 控制、四轮控制和轮腿混合步态。
- 已实现固定 40 字节 USB 解析、`0x10` 控制、USB/SBUS/NONE 仲裁和 150 ms 看门狗；正式 ASCII 接口仅保留只读 `p/Y`。
- 已实现 Python 上位机 codec、50 Hz 串口控制流、命令行联调和协议单元测试。
- 第一阶段软件已通过主机协议测试和 STM32 Debug/Release 构建，仍需在实体遥控器授权和机器人架空条件下完成硬件联调。
- 当前实机越障基线已通过直角绕杆、限高杆、大斜坡和木桥 A；其余常规障碍为第二阶段第一步目标，高墙仍单独列为第三阶段。
- `0x11` 当前只校验并丢弃；IMU 解码、姿态超限停止和姿态补偿属于第二阶段第二步。
- 116 mm 驱动轮已用于当前轮速和轮腿同步计算。

实际实现状态以代码和测试结果为准；规划文档中的接口不得被描述为已经完成。
